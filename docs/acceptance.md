# 1Agent 功能与流程验收

本文件是改动后的验收入口。自动化测试证明代码行为，实机验收证明已安装应用的操作效果；两部分分别记录结果。

## 每次改动怎么执行

1. **选范围**：日常修改按当前会话改动的功能，从下表选择相关脚本和实机用例。涉及共享组件时，补测行为直接受影响的调用流程。发版前执行下文的全量验收。
2. **准备构建**：需要应用模块的脚本使用当前源码生成的 Debug 构建。应用源码或资源变化后先构建；仅测试代码、验收入口或文档变化时，可复用未变化的应用构建。运行测试期间不要同时构建、安装或替换应用模块。
3. **跑脚本**：通过统一入口串行执行，检查退出码和报告。失败先定位并修复，再重跑失败项及受影响范围；不要把缺少环境、超时或未执行记成通过。
4. **跑实机流程**：核对所选用例中与改动相关的操作。需要安装时，按“安装检查”构建、安装并核对会话恢复。UI 验收以新安装的 `/Applications/1Agent.app` 为准。
5. **记录结果**：按文末模板报告本次范围、脚本结果、实机结果及未完成项。验收所选项目均通过才算完成；硬件、SSH 或系统权限缺失时明确标记阻塞，交由用户决定是否接受限制。

仅文档改动检查内容、链接和命令有效性；验收脚本改动运行它的回归测试，并实际执行受影响的入口。无需因此反复安装同一应用。新增功能或修复缺陷时，同步补充相关用例及脚本覆盖。

## 统一脚本入口

在仓库根目录执行：

```sh
# 查看范围或执行计划，不启动测试
python3 scripts/test-acceptance.py --list
python3 scripts/test-acceptance.py appearance --dry-run

# 日常示例：修改主题配色
python3 scripts/test-acceptance.py appearance

# 示例：修改文件与终端之间的切换
python3 scripts/test-acceptance.py terminal files

# 发版前全量自动化验收
python3 scripts/test-acceptance.py all automation compatibility stress
```

命令清单以 [test-acceptance.py](../scripts/test-acceptance.py) 的 `SUITES` 为准，可组合范围，相同命令只执行一次。默认日志写入 `build/acceptance/<时间戳-随机值>/`，也可用 `--output-dir <新目录>` 指定位置。`summary.json` 记录提交、未提交文件、范围、每项退出码和日志；实机状态始终保留为 `pending`，由验收记录补充。

入口不会自动构建、安装或重启。任一脚本非零退出时立即停止，后续项记为 `not_run`，并保留原退出码。焦点脚本自身只对外部应用接管前台造成的中断最多尝试三轮；真正的断言失败不重试，连续中断返回 `75`，仍属于未通过。其他原生窗口测试也需要前台环境，出现中断应保留日志并在桌面空闲时重跑，不能套用“自动忽略失败”。

## 环境与测试数据

- 使用 Apple 芯片 Mac、macOS 14+、完整 Xcode 和登录中的图形桌面；构建依赖以 [README](../README.md) 为准。原生窗口测试串行执行，运行期间不操作其他应用、不同时运行另一套 UI 自动化。
- `compatibility` 还需要 GNU Bash、fish、Elvish、Nushell、tmux，使用系统 Zsh/Vim。缺少依赖先补齐或记录阻塞；不要缩减用例冒充全量通过。脚本会使用剪贴板、短暂全屏和已连接显示器，避免同时编辑剪贴板。
- 新建专用验收终端；测试目录用 `mktemp -d /tmp/1agent-acceptance.XXXXXX` 创建。在其中准备带中文、空格的目录、文本和小图片。删除、覆盖、传输及清理只针对本轮拥有的测试数据。
- SSH 使用指定的非生产测试主机和本轮临时目录。自动化里的远程夹具不能代替真实 SSH 验收。线上主机写入仍按全局规范逐项授权；本验收约定不扩展线上操作权限。
- 用户已有终端只检查状态、保留输入与进程；不要借用它们执行测试命令，不改写用户 zsh 插件配置。记录测试创建的终端、命令和目录，结束时清理，恢复原有选中会话及临时更改的主题、快捷键等设置。

## 安装检查

用户已授权开发改动后直接安装重启，执行约定见 [AGENTS.md](../AGENTS.md)。每次仍须先检查所有窗口的本地和 SSH 会话，记录运行/等待命令及未提交输入，使用现有持久化机制保留它们；不要为安装终止 Shell、关闭用户会话或重启远程服务。

需要安装本次应用改动时执行 `make build`。完成后同时核对：构建成功、安装成功、实际进程来自 `/Applications/1Agent.app`、安装包与构建产物一致，以及 R01 的会话恢复结果。涉及 Bundle ID 时，用 `make test-defaults-migration` 验证迁移规则，实机再从旧包安装新版并核对原偏好、窗口布局和会话。编译成功不能替代安装或实机通过。
