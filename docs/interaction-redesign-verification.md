> 2026-10-13 更新：用户最新确认「保留两种文件布局，在同一入口互斥切换」。现只保留顶部文件菜单，旧开关和展开/收起入口已移除。当前实现与验证见 `../design-qa.md`；以下为历史记录，不能当作本次实机验收。

记录日期：2026-10-12。主界面实机检查分两次完成，分别为 2026-10-10 和 2026-10-12。

## 文件操作布局修正（2026-10-12）

用户实机反馈指出：360 pt 的单列文件区隐藏了本机文件窗格，妨碍从本机拖拽上传，文件名和操作空间也不足。现已调整：

- 主“文件”入口默认打开宽文件工作区，同时显示本机与远程目录；保留已有标签和浏览路径。已有工作区重新打开时不自动改为当前终端的主机。
- 文件模式下主工具栏明确显示“文件工作区”，隐藏终端分屏布局入口；返回终端后恢复终端布局操作。
- 若历史文件布局只有远程窗格，则复用已有本机标签或补充本机窗格；本机与远程混在同一窗格时，拆出对应标签以显示两端。现有其他布局与目录继续保留。
- “终端旁查看”作为明确的次要入口；可返回文件工作区或返回终端。终端视图留在原层级，切换时不重建连接。
- 新的窗口展示字段兼容旧快照缺失字段，旧窄文件区恢复为宽工作区。880×520 原生布局测试增加了两侧文件窗格的宽度与终端身份检查。
- `make test` 全部通过。实机已显示本机/远程双列，文件名和操作列可见，模式切换后两侧目录保持。
- 首轮拖拽验收被 UI 自动化工具的临时菜单控件 ID 失效阻断。继续验收时已加载并选中自建测试文件，确认“上传到远程”入口可用；鼠标自动拖拽没有生成远程文件，因此这条鼠标流程仍未验收通过。原有文件行拖放和 Finder 文件 URL 接收逻辑继续复用。
- 已完成真实传输集成校验：通过 `@testable import GooseAgent` 调用当前构建的 `1Agent.debug.dylib` 中的 `FileTransfer.copy`，将自建的 32 字节文本上传至远程 `/tmp`，读取远程内容校验，再下载并再次校验，均完全一致；本机和远程测试文件已清理。此结果验证应用自己的传输实现，独立于鼠标拖拽验收。
- 主文件入口重新打开时保留原远程主机和两侧目录；本次继续验收开始时的会话身份与顺序保持。验收期间新增的其他会话未被删除或修改。
- 最终安装后，实机从文件工作区返回终端再重新打开文件工作区，工具栏名称和布局菜单随模式正确切换，两侧仍保持原目录；切换前记录的 6 个 shell/SSH 进程全部继续存活。

下面的窄文件区描述现适用于“终端旁查看”模式，不再是文件操作的默认入口。

## 已实现

- 会话侧栏常显新建入口、搜索、工作区折叠和操作菜单；保留原有顺序、多选、右键和拖放。
- 多选操作条提供新建分组、移入分组、合并布局；窄侧栏中自动改为纵向排列。
- 工作区归属与面板布局分别维护；同一分屏组合显示派生的分屏编号，独立终端不显示。
- 工作区顶部提供布局、文件、更多入口；活动窗格使用标题强调和细边框；断线窗格保留可见重连入口。
- 文件区与终端并排，默认宽度 360 pt、最小 300 pt；终端至少保留 400 pt。空间不足时临时收起侧栏，关闭文件区后恢复。
- 窄文件区显示当前文件窗格，提供文字切换入口；展开后复用原文件网格、标签、预览和传输模型。
- 明确打开某终端的文件才更新对应主机和目录。切换终端、工作区和终端执行 cd 不自动跟随。
- 文件标签和文件区点击释放残留的终端焦点，保留文件筛选、路径编辑和列表已经取得的焦点；收起文件区恢复最后活动终端。
- 文件区展示、宽度、侧栏及工作区折叠状态保存到窗口快照。旧快照的整页文件模式迁移为展开的文件区；搜索和分屏编号不持久化。
- 搜索期间暂停侧栏排序拖动，快捷键编号仍按原会话顺序计算。隐藏的原生侧栏不参与拖放命中。
- 新增文案具有 en 和 zh-Hans 翻译，沿用 SwiftUI/AppKit、Ghostty 和现有主题材质。
